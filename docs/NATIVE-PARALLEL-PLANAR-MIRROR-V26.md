# v26 — Authorable native Beam + planar interface + finite mirror return (draft release candidate)

This candidate starts from production `main` `34a85e21985d13b4663473c20d7adc1d93fc4953`, after the **independently reviewed J11 PR #193** and its completed 11-workflow post-merge CI. It is a **new reusable engine composition**, not a new JEE answer, an image detector, or a handwritten optical propagation kernel.

## Initial release scope

A deterministic spatially finite native `Beam` reaches a planar dielectric interface; its refracted rays encounter an explicitly authored finite ideal mirror in the second medium, return through the same interface, and can cross an explicitly authored detector on the source side. This is a common **refraction → reflection → refraction** teaching system illuminated by genuine parallel rays, not a single-ray special-case model.

The pre-execution protocol `evaluation/native-parallel-planar-mirror-v26/frozen-protocol.json` was committed at `9c539084a56d5c533b3e8e93916315528222bb39`, **before** any native experiment. It freezes a synthetic 40-mm source and 10 raw experiment cases with an explicit index pair 1/1.5, 30° illumination, x=0 infinite PlaneGlass, x=60 mm finite vertical Mirror, x=−10 mm source-side detector, brightness 0.08, and density 0.2. Every numerical dimension/index is a research choice, *not* an original JEE problem fact.

### Test-only first step

`test/native-parallel-planar-mirror-v26-research.test.mjs` starts from a **genuinely valid public v19** `Beam + PlaneGlass + Detector` document. It clones only the compiled pinned native scene, then adds a native Mirror as a distinctly marked **RAW research** object. No v19 schema is widened or bogus public authoring qualification is asserted. The pinned PhyDemo commit `811f508d2b070898c241a568b0c167dcb8645251` emits every Beam sample, intersects every object, and computes Snell and specular directions itself. Our callbacks observe actual native emitted positions, interface encounters, mirror-reflected directions and detector crossings.

The independent analytical reference is **not** used to steer native light. For a planar interface with indices n0=1/n1=1.5 and initial incident angle 30°, Snell predicts r≈19.4712°, mirror-return *front-surface* displacement `2*60*tan(r)≈42.4264 mm`, and source-side detector inbound/outbound separation `2*60*tan(r)+20*tan(30°)≈53.9734 mm`. The 40-mm, density-.2 native Beam should emit 8 distinct samples, each crossing the interface twice and the mirror once, but these numbers require genuine native proof; a green JavaScript test alone does not certify all branches.

### Frozen negative controls

The experiment includes translation, normal incidence, higher index, denser source, mirror removal, too-short finite mirror, Fresnel-on (raw research only), zero ray-depth and processing stop. A mirror that misses/clips a sample cannot silently report eight successful mirror returns. A fully Fresnel-on run that truncates weak branches is incomplete; a raw observed ray is not an accepted public detector measurement. Any `simulationStop` or `truncation>0` is also incomplete; no fake hit list, image, irradiance or source-to-ray lineage may be synthesized.

## Implemented public v26 admission and limits (draft; independent review required)

The candidate now implements **the new explicit v26 profile** `native-parallel-planar-mirror-tracing`: one real finite native Beam + one vertical PlaneGlass + one independently finite vertical native Mirror entirely on the positive-index side, and 0–2 passive vertical detectors between the entire source segment and the interface. No lens, stop or extra refracting plane. This remains a draft until reviewed. The Beam must fit fully in the negative-index region, proceed toward the surface, have width 10–100 mm, deterministic samples 1–100 and brightness ≤rayDensity, with no physically assumed exterior index.

The finite mirror must be long enough for **every emitted sample's independently predicted first post-entry** Snell encounter to clear both endpoints by more than 0.1 mm; all source/detector/interface coordinates stay inside bounded world limits. This is a conservative authoring clearance check, not a routed ray. Actual pinned-native post-refraction/reflection rays must still pass completeness, numerical critical/grazing and finite-corner observation checks. Only `partialReflection:false` is eligible for v26 initially, with equal-or-higher second-medium index and initial Beam incident angle 0° through +60° relative to the positive-x normal; genuine native TIR is not disabled. The validator now rejects Fresnel-on, mirrored endpoints within 0.1 mm, high-to-low index entry, Beam starting inside/straddling glass, tilted mirror, foreign optical families, detectors in the wrong medium, deterministic initial/return detector endpoint hazards, stale source edits and unsupported scenes. Older saved v5 and v19 remain bit-for-bit unchanged.

Do **not** use an author-provided ray/path string to make this work. Reuse native `Beam`, `PlaneGlass`, `Mirror`, ordinary public scene authoring and qualified measurements. Ensure a 32-event detector-hit cap is upheld rather than silently expanding it. The new v26 integration should get **one focused independent review after a final full CI run**, not a separate review of this feasibility-only probe. Keep PR draft and unmerged until cleared.

## Public v26 native, CLI and Chrome acceptance (not a 3D image)

The fully authored example `examples/native-parallel-planar-mirror-v26.json` uses the ordinary `opticsim-problem-v1` JSON scene, with six existing native observables: Beam emissions, glass interactions, first glass event, mirror reflections, detector crossings and detector-hit-events. The existing pinned compiler produces exactly `Beam`, `PlaneGlass`, `Mirror`, `Detector`, in source-provided order, with no custom ray tracer or ray-editing adapter. In baseline density 0.2, eight real source samples cross the source-side detector twice, the PlaneGlass twice and the finite Mirror once each. The original source and returned beam are sampled geometrical rays, not continuous irradiance, a focus image or calibrated optical power.

`test/native-parallel-planar-mirror-v26.test.mjs` independently asserts ordinary public `prepareScene`/save/parse, pinned `evaluateDocument` and `evaluateObservables` counts, necessary signed Snell and specular invariants at actual native callbacks, translations, index changes, beam width/density changes, rejected clipped mirror endpoints, detector endpoint hazard, multiple/tilted optic refusals, numerical stops and clean suppression. At density 0.4, 16 emitted samples produce **32** detector callbacks and the bounded position list is still admissible. At density 1, **40 samples generate 80 real detector crossings**; the existing `detector-hit-events` limit 32 **withholds the entire position list**, while native total crossing counts remain actual readings. The hit cap is not widened or clipped.

The public `scripts/native-parallel-planar-mirror-v26-acceptance.mjs` exercises the actual source-bound JSON problem handoff, native execution, qualified portable exports, material edits and four refused inputs **before any native run**. `scripts/native-parallel-planar-mirror-v26-browser.mjs` uses a real headless Chrome session to load the qualified v26 package, verify native measured counts, edit Beam width and glass index, save a changed qualified package, reject a clipped Mirror and re-open the saved version with fresh readings. It archives browser screenshots and exact evidence. Both are mandatory additions to the existing optical-composition CI; green Node-only execution is not sufficient to claim browser acceptance.

**Historical scope:** v5 SingleRay+PlanarGlass+Mirror and v19 native Beam+PlanarGlass or Beam+Lens remain separately versioned and validated. The only necessary old-test adjustment is to keep the historical 31-profile count **exact**, while separately asserting precisely one new v26 profile (32 total). No pre-existing original optics, upstream pin, source-language model, geometric calculations, observables or historical answer datasets are changed. The new capabilities extend what the **engine can actually represent** rather than promising to solve J08 or infer missing material.
