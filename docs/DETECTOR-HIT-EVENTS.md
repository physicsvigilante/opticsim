# Bounded native detector-hit positions (requested observation only)

## Purpose and provenance

`detector-hit-events` is a **native observation**, not a new optical object,
analytical ray solver, image detector, inverse answer or general ray history.
Only an explicitly selected observable enables collecting coordinates in the
ordinary native execution pipeline. The historical `detector-crossings` and
`detector-signed-power` values retain their exact meanings and output shapes.

The same observer works with already admitted components: passive authored
`ray-detector` segments and pinned PhyDemo `Detector.onRayIncident(ray,index,point)`.
Opticsim snapshots that actual callback point and incoming direction before the
native detector mutates its ray, then invokes the original callback **once**.
No inferred or traced ray intersections, synthetic source IDs, ray pairing,
ray reorderings or additional ray propagation are introduced. The point is
returned in scene **millimetres, x right, y up**. `incomingUnit` is the unit
travel direction immediately before the hit, also x-right/y-up;
`distanceFromP1Mm` runs along the authored detector segment from its first
physical endpoint (the endpoint generated by the existing orientation contract).

## Request contract

Use the existing native `opticsim-problem-v1` and qualified-observables
interfaces. Add e.g.

```json
{
  "id": "screen-hits",
  "kind": "detector-hit-events",
  "componentId": "Dhit"
}
```

The measured `value` is an **array in native callback order**, each event:

```json
{
  "pointMm": {"x": 85, "y": 6.18},
  "incomingUnit": {"x": 0.993, "y": -0.114},
  "distanceFromP1Mm": 86.18
}
```

These figures are **illustrative rounded values**, not a new physical
default or a source question interpretation. The exact stored values remain
unrounded. `unit` and method metadata are separate from the array; no `rayId`,
`sourceId`, `path` or image-status field is exposed.

An unambiguous native miss produces an available empty list `[]`; it does not
mean no light could reach the detector at other sampling densities. Existing
count and signed native power readings remain separate. A pair of sequential
crossings cannot be assumed to be the same ray, especially for sampled beams,
multiple sources and partial Fresnel branches. Two recorded hit positions can
support a specifically defined **geometric comparison**, but the core does not
claim a physical lateral displacement without verifying which hits to compare.

## Qualification and refusal

- At most **32 hit events per detector per complete native run** are retained.
  Overflow withholds **the entire list**, never presenting 32 clipped entries
  as if complete. Native crossing counts remain available on a complete run.
- A native callback hit must have finite coordinates and valid incoming direction,
  be within **1e-5 mm** of the detector segment, and lie at least **0.01 mm**
  from either endpoint. Endpoint/corner ambiguity withholds the complete list;
  these are *observation* guards, not new PhyDemo intersection rules.
- On native failure, stop, truncation, undefined behavior or stale execution
  evidence, results are **suppressed**. Raw hit arrays are withheld even from
  execution diagnostics on incomplete runs. Missing opt-in capture or inconsistent
  native event/count data is **unavailable**, not an invented zero.
- Fresh, hash-matching qualified source/observation packages preserve component
  identities and assumptions. The package never embeds accepted results from a
  previous scene. Every physical edit requires a new native execution.
- Changing sampling, source brightness, emission, components or source position
  may change recorded events. Signed detector power is not absolute irradiance,
  and a hit list does not certify continuous visibility or image formation.

No saved-scene schema, model version, PhyDemo pin, numerical ray budget,
source authoring default, or existing result-request kind is modified.

## What was actually qualified

Two **frozen synthetic motivating cases** were observed test-only before the
production implementation: a planar glass and mirror with two crossings of one
exact native ray; and a finite lens/mirror return with 11 sampled crossings
from six emitted rays, explicitly **not** paired as source-specific tracks.
Separate Snell/reflection checks and identical uninstrumented native readouts
established callback coordinates and exactly-once delegation.

A third, previously reserved finite prism + external opaque blocker + detector
case was run **only after production source and checking code hashes were frozen**.
It completed with two native glass encounters, one detector hit, zero blocker
absorptions, and a hit at `(85,6.180474192751514) mm`. No production fix was
made for it. This is **same-assistant previously exposed developmental transfer**,
not a blind held-out independent model or classroom test. Freeze hashes and the
retained first run reside in local ignored evidence; public regression inputs
are `test/fixtures/detector-hit-transfer*.json`.

A native, public-workflow seven-case acceptance covers completed hits, a changed
material index, a miss, sampled lens/mirror crossings, >32 hit overflow,
Fresnel incompleteness and an invalid scene. The first harness incorrectly
expected process exit 1 for a rejected complete request, but the normal public
workflow returns exit 2 when requested coverage is missing; the original harness
failure was retained and the corrected v2 run passed.

**Integration correction after the reserved case:** The local source snapshot used
for the first R1 execution lacked two already-merged qualified v10-to-v11
composition-upgrade interfaces. Before publication, those were restored in
`src/exploration.js` and `scripts/qualified-scene.mjs` without changing this
native hit observer or its physics. The original pre-execution freeze file is
unchanged; an additive `detector-hit-integration-rebase.json` records the later
source hashes, and replays after this correction are exposed regressions, **not**
a still-frozen held-out transfer. The qualified upgrade must not be dropped to
make this measurement work.

Run after regular setup:

```sh
npm test
node scripts/detector-hit-acceptance.mjs
npm run build
node scripts/detector-hit-browser.mjs
```

The acceptance writes only under ignored `test-artifacts/`; its directory must
be fresh. The real-Chrome script exercises the existing qualified viewer,
physical edits, export/reopen, overflow and incomplete suppression. Local Chrome
may block localhost before the application loads; that is a blocked test, not a
browser pass. The normal repository CI runs the browser checks on the exact PR
source. No new UI form, independent LLM, provider credential or public deployment
is part of this capability.
