# Opt-in v9 finite-hit native numerical diagnostic — Stage 1, NONCERTIFYING

**Release status:** Stage-1 **draft production-code candidate**. Requires new independent Chat B R2 implementation/code and physical-evidence review, tests and explicit separate owner merge approval. The underlying pre-implementation [PR #88 design v2](https://github.com/physicsvigilante/opticsim/pull/88) received independent **design-only** approval [here](https://github.com/physicsvigilante/review_sandbox/blob/main/projects/opticsim/pr-88/reviews/review-02-chat-b.md). **Stage 2 mandatory qualification is not approved or implemented**.

## Physical basis and claim

The pinned unmodified PhyDemo `811f508d2b070898c241a568b0c167dcb8645251` may report a completed near-critical finite-Glass trace whose *actual recorded* incoming binary64 ray points backward to its recorded finite-edge incident point. This is a **represented-line consistency issue**, not a correction of the mathematically exact critical-angle branch or a solved original question. Other properly completed runs may be physically valid even when this additional diagnostic is unavailable. This milestone only provides an **explicit, optional diagnostic readout**; it **never** replaces the native intersection algorithm, reroutes rays, adjusts brightness/density/thresholds, or withholds previously canonical optical measurements.

## Existing v9 scope only

The diagnostic request uses the normal companion observables contract:

```json
{"id":"native-geometry-check","kind":"finite-hit-numerical-diagnostic","componentId":"G1"}
```

`G1` must be the **already authored unique polygon-dielectric** in a validated **schema-v9** `polygon-dielectric-tracing` scene: exactly one strictly convex four-vertex homogeneous Glass, **1–4 explicit SingleRay sources**, **0–2 passive external detectors** and no other physical object types. It does not silently enable polygonal variants in v4/v5/v7/v8, multiple glass regions, 3D material geometry, apparent images, or the held-out original question. Material indices, vertex coordinates, Fresnel policy and native budgets all remain those explicitly authored for the ordinary existing scene.

The request is optional. With no request, **not a single extra finite-hit observer, callback, raw diagnostic or result field is installed or published**. Qualified package exports retain this requested kind, but **never** retain observed ray coordinate snapshots or an accepted prior run's diagnostic result. Raw sandbox imports clear the request and historical qualification. The existing browser can display this readout without a separate ray tracer, using its ordinary native/qualified run and revision gate.

## Observer and exact-representation mechanics

- **Single actual native owner:** The existing per-instance Glass `onRayIncident` observer captures pre-mutation *scalar* `ray.p1`, `ray.p2` and native callback `incidentPoint` only when the advisory is requested, then invokes the original callback exactly once with identical `this`/arguments/return. Native `newRays` references, detector mutation, signed power and ray scheduling are unchanged. Exact arithmetic is **not** executed in the native callback. Capture failures must record advisory unknown without preventing native delegation.
- **Entire authored source and observer coverage (Chat B F-02):** Before emission, each SingleRay, the sole Glass and each detector's exact native method/instance is registered; each native source must start once and return **one distinct actual JavaScript emitted-ray object with finite numeric `p1.x/p1.y/p2.x/p2.y`, nonzero finite ray direction length and valid native identity**. An object `{}`, missing endpoints, nonfinite coordinates, string coordinates or a degenerate zero-length direction is **unknown**, even if the native source meter reports one emission. Terminal handler identity and source, Glass and detector meter checks must remain consistent; a self-counted emission meter is not independent corroboration. A zero-interaction trace is accepted as sampled `checked-no-hit` only after this positive **valid** emitted-ray geometry and registration coverage.
- **Bounded exact math after terminal native event:** At most **128 incident scalar snapshots** may be stored, with total callback counts tracked even on overflow. Every actual finite callback must be covered, or the report is `unknown`; native propagation itself is not limited to 128. Compute exact rational geometry on represented **binary64** ray/edge coordinates with built-in `BigInt`, requiring the unique intersection to have strictly positive forward parameter, distance squared **strictly above** the existing native segment cutoff, an interior finite-edge parameter and full 0.01 mm vertex clearance. The actual native-reported incident point and independently computed point must also agree.
- **No invented floating-point error envelope:** A universally validated, scale/conditioning-aware point error bound **does not yet exist**. Thus even a tiny nonzero exact reported-point discrepancy is conservatively **`unknown`**, not `checked`, unless a more decisive strict nonforward, cutoff, or far-outside-edge contradiction is independently established on that incident. The reported native point `(10,7)` for ray `(0,5)→(1,5)` intersecting x=10 at `(10,5)` cannot be certified by a forward line crossing alone. The diagnostic does not call small floating discrepancies a proven native bug; it also does not mistake a `checked` exact equality for proof of correct optical branching.
- **Unknown vs inconsistent (Chat B F-01/F-03):** Robustly nonforward/subcutoff/outside-finite-face intersections on **well-conditioned**, uniquely grounded native incidents may be flagged **`inconsistent`**, with a machine-readable subtype. Even if represented binary64 rays intersect the face at the exact native-reported point, a *nearly parallel* ray/face angle is **`unknown / NEAR_PARALLEL_FINITE_HIT_ILL_CONDITIONED`** when the magnitude of the 2D cross product of normalized native ray and finite-edge vectors is at most **`sqrt(Number.EPSILON)` ≈ 1.49×10⁻⁸**. This *dimensionless conditioning-only conservative classifier*, roughly limiting intersection angular condition number to `1/sqrt(epsilon)`, **is not a PhyDemo ray cutoff, a physical grazing threshold, or a validated native point-error tolerance**; it may withhold legitimate shallow hits. Near vertices, coincident rays, native point uncertainty, unproven callback closure, failed/missing hooks and over-cap streams also remain **`unknown`** and are never published as clean. **Warning precedence:** a well-founded same-run exact represented-line contradiction remains **`inconsistent`** even if another native warning is present; absent a proven contradiction, a warning forces **`unknown / NATIVE_WARNINGS_NOT_CERTIFIED`**, never clean. This is not a claim that a warning itself proves an optical error. Failed/stopped/truncated/undefined native runs remain **`suppressed`**, with raw geometry withheld from ordinary result snapshots and CLI/browser visible output.

## Noncertifying result and answer semantics

The resulting `finiteHitDiagnostic` is an ephemeral per-run summary with no public ray endpoint lists, source IDs, rayIndex history, image inference, native correction or ray path. It includes `status`, `reasonCode`, `observedGlassIncidents`, `checked`, `unknown`, `conflicting` and `limit`, plus `nativeMeasurementQualificationUnchanged:true`. On a valid completed run, `evaluateObservables` exposes it as **`status:"advisory"`**, method `advisory-native-finite-hit-binary64-v1`.

**An advisory is never an answered optics quantity.** The public `runProblemEvidence` requested-result coverage deliberately excludes `status:"advisory"` from `available`; for a request solely asking for this diagnostic, public workflow exit code may be **2** even when native execution and advisory capture succeed. This distinction prevents numerical-safety introspection from masquerading as a solved image/material/refraction question. The browser evidence panel separately labels **NONCERTIFYING native diagnostic**, distinct from physical observations and conditional predictions.

- `checked`: every actual observed finite hit passed the **strict exact necessary** representation test. **NOT a proof of correct native physics**, valid critical-angle branch, or source interpretation.
- `checked-no-hit`: every required source and callback was observed but the native Glass recorded zero actual incidents. This is only a sampled absence, **not continuous darkness**.
- `inconsistent`: at least one represented finite-hit callback violates a proven forward/cutoff/finite-edge predicate. The viewer explicitly cautions that **canonical native optical measurements are NOT independently certified by this diagnostic**, but the Stage-1 rule **does not withhold or rewrite those measurements**.
- `unknown`: the observer, geometry, point-agreement or cap could not certify every event, or a native warning occurred. Unknown is neither "clean" nor proof of a native defect.
- `suppressed`: no complete native run to qualify, or a failed/stopped/truncated/undefined/stale execution. An old successful advisory cannot be reused after a revision.

## Acceptance, threats and limitations

Review `test/finite-hit-diagnostic.test.mjs` for independent dyadic geometries, the wrong-hit-point counterexample, **reviewer F-01 near-parallel and translated classifier controls**, **F-02 missing/malformed native emission endpoints preventing a false-clean zero-hit**, **F-03 native-warning/robust-contradiction precedence**, real pinned v9 native readout parity, no-request snapshots, zero-hit versus silent missing source, hook-replacement/capture failure, 128/129 injection, warnings/incompleteness and legacy scope refusal. The public [acceptance script](../scripts/finite-hit-diagnostic-acceptance.mjs) executes fully authored v9 scenarios with 0/1/2 detectors, 1/2/4 sources, Fresnel on/off and a previously exposed rotated near-critical fixture **without assuming a deterministic critical branch**. It reports actual native statuses and elapsed time/heap changes rather than silently increasing native limits to complete all cases.

The real [Chrome script](../scripts/finite-hit-diagnostic-browser.mjs) exercises source-backed ordinary packages, viewer warnings, qualified export/reimport, raw import clearing, valid no-hit and normal/multiple-source cases, full Fresnel native completion/suppression and a variable critical case. Native source code is unchanged; no graphical ray-parentage overlay, school study or continuous-wave optical truth is claimed.

**Residual concerns for the independent implementation reviewer:** truly neutral capture at near-critical floating instability is not independently proven by same-source repeated runs (unchanged canonical runs themselves vary). A strict point-equality rule can label many physically correct rounded hits `unknown`. The provisional 128-event bound is an **availability/resource limit**, not a demonstrated maximum for legitimate full-Fresnel optics. The current Stage 1 does not perform a future mandatory no-request/CLI/native-metric suppression and must not be promoted to one without a separate owner policy decision and new R2 review.

**Do not merge this code without independent R2 implementation review and separate owner approval. Do not merge PR #87 or #88 research/disposable workflows.**
