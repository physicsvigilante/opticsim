## Source evidence and precise risk

[Research-only PR #87](https://github.com/physicsvigilante/opticsim/pull/87) executed 80 fully specified synthetic apparatuses using 160 pinned native runs (four existing refractive families × five critical-angle regimes × four transformations). It recorded 71 completed, 8 incomplete (consistent with trapped circular TIR rays exhausting depth) and 1 failed v9 quadrilateral run. Critically, a **different v9 quadrilateral run completed despite a demonstrated invalid finite-edge hit**.

The independent [exact binary64 rational line reference](../scripts/exact-line-reference.mjs) applied to actual recorded native callback inputs found:

| Actual v9 case | Native second hit | Exact represented incoming ray vs actual finite face | Native run |
|---|---|---|---|
| Translated, computed-critical | 0.000168931960388 mm away | t = 0, intersection is at the ray's start, below the pinned minimum step | failed (native face observer also detected ambiguous evidence) |
| Rotated 37°, computed-critical | 0.000582185612597 mm away | t ≈ -4.2871338283e-7, intersection is behind the recorded ray's start | **completed** |

Both native distances exceed the pinned nominal minimum step of 1e-6 mm; the **exact represented** steps do not. They are observable inconsistencies with the engine's *own binary64 coordinates*, not a universal physical root-cause proof, ray-path solver or justification for changing a cutoff. In the independent offline inspection of the PR #87 artifact, all 83 actual finite-glass native callbacks in the v8/v9 subset were tested against their individually selected finite edges: these **two** failed forward/cutoff checks; the other 81 passed that particular necessary check. The prior two-planar-interface B05 failure is separate. Circle exact-critical transmission/TIR branch changes are an additional numerical sensitivity, not proof of this finite-edge failure. Trapped TIR incompleteness is not automatically an intersection defect.

**Target harm:** Native simulationComplete alone can be insufficient to certify native-derived measurements from a run containing a nonforward finite intersection.

## Proposed normative observer and exact geometry contract

1. **Preflight and single owning callback (future Stage 1):** Before emission, reconcile the exact set of authored v9 source IDs/native SingleRay instances, the single authored Glass ID/native instance/four finite edges, and all 0–2 authored detector IDs/native instances. Install **exactly one owning per-instance wrapper** on each participating original callback method, never an extra nested native-calling wrapper. Retain actual pre-mutation ray and incident-point references/immutable scalar copies; invoke the pinned original **exactly once** with unchanged `this`/arguments; return its original exact object and `newRays` references; preserve native exceptions and ray mutations. Capture errors must fail the **diagnostic** after safely delegating native propagation, never be silently swallowed or prevent the original callback. **No BigInt, logging, asynchronous work, or exact geometry in the hot callback**: perform post-run arithmetic on bounded scalar snapshots. Explicitly test equivalent observer ordering and benchmark impact; arbitrary separate exact-critical run-to-run equality is not a valid proof of neutrality.
2. **Actual pre-mutation evidence:** For **each** native Glass onRayIncident callback, record from args[0] the original ray's actual binary64 p1 and p2, and from args[2] the actual engine-chosen incident point, before the pinned method mutates the ray. Do not infer source ID from rayIndex or from geometry. Object identity is needed only for bounded observability and interleaving defense; don't manufacture a complete ray history.
3. **Unique authored finite face, checked from both sides of the claim:** Ground the **native-reported incident point** on exactly one authored finite edge within the existing 1e-5 mm face residual, and classify a point within 0.01 mm of **any relevant finite-edge vertex** as **unknown**. Independently derive the represented-ray/edge intersection in rule 4; apply the same finite-segment and vertex/corner ambiguity rules to the **computed** intersection itself, not solely the reported native point. Missing/nonfinite point, duplicate face membership, overlap, very-near vertex or unresolved face identity → **audit unavailable/unknown**, never a guessed face. Observer delegation must remain identical.
4. **Independent exact binary64 forward/finite/intersection-point predicate:** Convert only the original snapshotted ray and authored native finite-edge endpoints into exact dyadic rational values; compute unique intersection `t`, finite-edge parameter `u`, and exact point `P*`. Require **strict `t > 0`**, exact squared step **strictly above** the unchanged native `Simulator.MIN_RAY_SEGMENT_LENGTH_SQUARED × scene.lengthScale²` and interior finite `0 < u < 1` outside the existing 0.01 mm vertex ambiguity region; **the native-reported point must also agree with independently computed `P*` within a justified, documented and adversarially tested numerical uncertainty envelope**. `u = 0`/`u = 1`, tolerance-borderline and ill-conditioned crossings are **unknown**, not clean or automatically a demonstrated native bug. The old `exactLineReference` checks supporting infinite lines only, so a future implementation must explicitly validate `u` and reported-point agreement. No arbitrary global 1e-5 mm equality threshold or bit-for-bit reported-coordinate equality is assumed; if an error envelope cannot be justified for that event, report **unknown**, not `checked`. Reference code runs after native execution on bounded snapshots; compare a fully distinct mathematically consistent but misreported hit `(10,7)` against actual `(10,5)` as an explicit negative.
5. **Contradiction, unknown, and no promotion:** For an actually observed, uniquely grounded and numerically well-defined native event, a provably absent forward unique intersection (including an exact parallel ray/face), `t ≤ 0`, **strictly subcutoff** step, robust outside-finite-edge `u`, or a callback point demonstrably outside an independently established uncertainty envelope is a **represented-geometry contradiction** (`NATIVE_FINITE_HIT_GEOMETRY_INCONSISTENT`, with subtype). A coincident/degenerate ray and edge, endpoint, unresolved finite face, uncertain point-error bound, near-tangent conditioning, failed exact arithmetic or absent callback/identity ledger is **unknown** (`NATIVE_FINITE_HIT_AUDIT_UNAVAILABLE`), not an accusation of incorrect optics. Both produce a caution/refusal in research or opt-in diagnostic output; **neither changes production v9 measurements during Stages 0/1**. Only a separately approved future Stage 2 gate could withhold all trusted native-derived v9 measurements. No reconstructed incident point, corrected ray, adjusted native status or textbook claim.
6. **Bound all events, never clip or assert complete:** **128 actual Glass callbacks** is an **unproven diagnostic policy limit**, not a native physics cap. Count *all* actual callbacks after crossing the limit (bounded integer), continue native propagation unchanged, mark `NATIVE_FINITE_HIT_AUDIT_UNAVAILABLE` for that run and discard the possibility of `checked`; the first 128 snapshots cannot establish complete coverage. Before any production authorization, test 128/129 by *test-only injected event streams*, and assess actual completed multi-source, full-Fresnel, 0–2 detector, weak-branch and long-lived native scenarios. Record CPU time, BigInt bits/operations/memory and real-Chrome responsiveness; choose measured bounded cost or leave diagnostic unavailable. Never claim that a cap overflow proves a physics error or truncate a trusted event list.
7. **All sources and all hooks, checked per execution:** Before one real terminal native event, positively prove the exact source/Glass/detector registry and native method identity/install ownership. Each authored SingleRay must actually start once and return exactly one valid registered native emission (without treating a self-summed source meter as an independent proof); every actual Glass incident must be seen by the owning interface hook, with same-run native meter equality; all detector hooks must remain installed. Missing, duplicate, bypassed, malformed or replaced source/incident hooks fail *closed* for the diagnostic. A genuinely zero-hit run is `checked-no-hit` **only after positive source start coverage and handler ownership**, not as evidence of continuous darkness. A per-execution/private run epoch PLUS current scene SHA/revision/sequence prevents stale A→B→A publication, including a new run with the same SHA. No persistent ray tokens and no inferred ray-history graph.

## New adversarial evidence: ordinary exact-critical runs are themselves variable

The initial test-only CI of this PR **failed and must remain a recorded failure**. The first captured batch had a translated v9 scene with differing ordinary and instrumented terminal status; a second run captured a rotated v9 scene with **four** ordinary vs **six** instrumented interface incidents. These differences were **not** corrected by changing the authored geometry, source ray, physics, Snell threshold or native core.

A subsequent diagnostic added **eight alternating executions** (four plain canonical runs and four read-only-wrapper runs) for **each** original exact-critical v9 case. In those actual retained runs, plain canonical executions **themselves** varied with run ordering:

- Translated: ordinary statuses included **completed** with 3 incidents and **failed** with 4 incidents (the latter had native invalid face observations), without source changes.
- Rotated 37°: ordinary runs remained completed but had **5 or 6 incidents**, with matching variation in processed segment totals.
- Read-only-wrapper runs also varied, and some individual paired canonical and instrumented runs had different event totals.

**Consequence:** near/exact-critical **cross-execution trajectory equality is not a valid design acceptance oracle** for this pinned native branch. The variation's mechanism (including possible upstream state, V8 optimization, numerical conditioning and wrapper influence) is **not isolated**. Do not assert the wrapper causes the discrepancy merely because two runs differed; equally, do **not** claim behavior-neutral instrumentation is proven merely because some pairs happened to agree. A future release must preserve native return/input invariants **within the same callback and same actual run**, and evaluate every observed forward hit of **that run** before promoting measurements. Ordinary far-from-critical and normal-incidence wrapper parity remains a separate regression requirement. No previous first failed CI report or original PR #87 observation is rewritten.

**Test correction in the draft research script:** the counterfactual shadow qualification now belongs to the **instrumented execution whose events were actually checked**, not to a different ordinary execution's native status. Repeated original exact-critical traces and all status/count discrepancies remain visible in the raw research report. The final research gate tests controlled far-angle/normal invariants, exact finite-segment checks and at least one actual contradictory native event; it does **not** demand all independently executed critical cases reproduce an identical ray history. This is not permission to merge a production gate.

**Revised post-review conclusion:** These actual native critical variations **block automatic mandatory v9 qualification rollout**. Stage 0 research remains unchanged, Stage 1 is proposed only as opt-in **noncertifying** diagnostics after separate owner approval and code-level R2 review; Stage 2 mandatory refusal is a separate possible future decision only after justified point uncertainty, same-run observer invariants, load measurements and complete publication gates. Neither benign cross-run matching nor current green research CI proves observer neutrality. Require a new independent **design-only** targeted verdict on these changes, followed by future owner-controlled implementation stages.
