**Status:** PRE-IMPLEMENTATION CONTRACT AND TEST-ONLY SHADOW STUDY. No production qualifier, ray physics change, upstream PhyDemo patch, scene schema change, public result or browser behavior is included. A separately approved code milestone and new independent R2 code review are required before any deployment/merge.

**Production base:** Opticsim main at fa158fc78da7a35b6a02eaed58c0cdbd4b699220 (750/750 Node and 11/11 workflows after PR #86), pinned unmodified PhyDemo 811f508d2b070898c241a568b0c167dcb8645251, Node 24.19.0. Existing src/planar-media.js, src/polygon-dielectric.js, src/finite-glass-geometry.js, src/adapter.js, src/observables.js, CLI, Session and QualifiedUI contracts remain authoritative.

## Source evidence and precise risk

[Research-only PR #87](https://github.com/physicsvigilante/opticsim/pull/87) executed 80 fully specified synthetic apparatuses using 160 pinned native runs (four existing refractive families × five critical-angle regimes × four transformations). It recorded 71 completed, 8 incomplete (consistent with trapped circular TIR rays exhausting depth) and 1 failed v9 quadrilateral run. Critically, a **different v9 quadrilateral run completed despite a demonstrated invalid finite-edge hit**.

The independent [exact binary64 rational line reference](../scripts/exact-line-reference.mjs) applied to actual recorded native callback inputs found:

| Actual v9 case | Native second hit | Exact represented incoming ray vs actual finite face | Native run |
|---|---|---|---|
| Translated, computed-critical | 0.000168931960388 mm away | t = 0, intersection is at the ray's start, below the pinned minimum step | failed (native face observer also detected ambiguous evidence) |
| Rotated 37°, computed-critical | 0.000582185612597 mm away | t ≈ -4.2871338283e-7, intersection is behind the recorded ray's start | **completed** |

Both native distances exceed the pinned nominal minimum step of 1e-6 mm; the **exact represented** steps do not. They are observable inconsistencies with the engine's *own binary64 coordinates*, not a universal physical root-cause proof, ray-path solver or justification for changing a cutoff. In the independent offline inspection of the PR #87 artifact, all 83 actual finite-glass native callbacks in the v8/v9 subset were tested against their individually selected finite edges: these **two** failed forward/cutoff checks; the other 81 passed that particular necessary check. The prior two-planar-interface B05 failure is separate. Circle exact-critical transmission/TIR branch changes are an additional numerical sensitivity, not proof of this finite-edge failure. Trapped TIR incompleteness is not automatically an intersection defect.

**Target harm:** Native simulationComplete alone can be insufficient to certify native-derived measurements from a run containing a nonforward finite intersection.

## Narrow first proposed implementation scope (NOT included here)

- Only existing schema/adapter **v9 polygon-dielectric-tracing**: exactly one strictly convex quadrilateral native Glass, 1–4 authored explicit single-ray point sources and 0–2 external passive detectors, with existing geometry, medium indices, true native Fresnel policy and numerical limits unchanged. No lens, mirror, circle, triangle, multiple interfaces, nested regions, new LLM request type or new authoring schema is implied.
- **Mandatory for claiming a qualified v9 native measurement**, rather than an optional switch which silently allows known inconsistent evidence to pass. This intentionally tightens v9 readout semantics, so production implementation requires explicit owner approval and R2 review. Prior non-v9 output shapes and historical first attempts must remain byte/meaning compatible.
- Passing the check means only **all actually observed native finite-Glass incident callbacks satisfied a necessary represented-straight-ray forward/finite-segment consistency condition**. It does not prove complete physical trajectory fidelity, numerical convergence, optical image formation, continuous illumination, correct critical-limit branching, original source interpretation or Watts.

## Proposed normative observer and exact geometry contract

1. **Install before source emission:** Match the exact validated authored Glass ID to the actual native instance and all four finite edges, then extend the existing *single owning per-instance native interface callback* with an ordered read-only snapshot hook. The pinned original method must receive identical this/arguments, run exactly once and return the **same** object including native newRays array. No competing native-calling wrapper or new propagation. Preserve source and detector meters, signed native power, all interface first/face events, ray budgets, callback ordering, and all legacy optics.
2. **Actual pre-mutation evidence:** For **each** native Glass onRayIncident callback, record from args[0] the original ray's actual binary64 p1 and p2, and from args[2] the actual engine-chosen incident point, before the pinned method mutates the ray. Do not infer source ID from rayIndex or from geometry. Object identity is needed only for bounded observability and interleaving defense; don't manufacture a complete ray history.
3. **Unique authored finite face:** Ground the actual incident point on **exactly one** authored finite edge within the existing face residual of 1e-5 mm, and reject vertices within the existing 0.01 mm clearance. Missing/nonfinite native point, missing/duplicate edge membership or near-vertex geometry -> **audit unavailable**, not a guessed face or demonstrated physical defect. Native callback result must still be delegated once.
4. **Independent exact binary64 representation:** Convert only actual snapshotted ray endpoints and authored edge endpoints to rational numbers representing their *binary64* values. Compute their two straight-line intersection parameters using BigInt rational arithmetic. Require a unique line intersection, **strictly positive forward distance** (not t=0 and never t<0), squared step **strictly greater** than the already pinned Simulator.MIN_RAY_SEGMENT_LENGTH_SQUARED × scene.lengthScale², and exact finite edge parameter **0 ≤ u ≤ 1**. The **finite segment** condition matters: the existing standalone exactLineReference establishes only supporting infinite lines and must be extended/checked before release. This is a validation of observed represented geometry, not Snell, ray routing or a replacement intersection algorithm.
5. **Contradiction vs uncertainty:** An actually observed unique finite hit with exact parallel/coincident, nonforward, subcutoff, or outside-face segment intersection is **NATIVE_FINITE_HIT_GEOMETRY_INCONSISTENT**, qualified reason subtype preserved. If any installed hook is absent/misordered, callback evidence malformed or ambiguous, exact arithmetic fails, source/incident counts disagree, or a memory bound overflows -> **NATIVE_FINITE_HIT_AUDIT_UNAVAILABLE**. Both must **withhold qualified native-dependent v9 readouts**. Neither means the native simulator failed physically in all respects, and neither supplies a repaired coordinate or ray.
6. **Bound all events, never clip a complete result:** Proposed **128 actual Glass incident callbacks per run** as a conservative audit cap for later adversarial/performance assessment; native processed-ray and depth budgets unchanged. Count every native callback even after cap, continue native execution normally, mark audit unavailable and do not treat first 128 events as sufficient proof. Never retain an unbounded parent graph or leak partial geometry to public JSON.
7. **Run completeness and identity:** Only a real terminal native event, successful preflight/observer ownership, verified native source start coverage, incident-meter count agreement, zero unknown/cap events and passing checks for **every** actual incident can qualify the *separate* forward-consistency status. A zero-hit run can be called only 'checked-no-glass-hit' after actual source emission and callback installation, never a proven continuous dark region. Existing revision/sequence defenses must reject stale A→B→A callbacks despite matching scene hashes. No new ray token across runs.

### Proposed public qualification policy

Keep the **native execution terminal status truthful**; a completed native run that contained an invalid represented forward intersection should still report native.status=completed, NOT a made-up native failure.

| Evidence condition | Additional numerical qualification | Requested native measurement outcome |
|---|---|---|
| Native pending/failed/stopped/incomplete/truncated/undefined or stale revision | suppressed / NATIVE_INCOMPLETE_OR_STALE | Existing suppression; no accepted readout |
| Native completed + confirmed invalid forward/subcutoff/outside-finite-face hit | unqualified / NATIVE_FINITE_HIT_GEOMETRY_INCONSISTENT | Withhold native-derived v9 detector counts/signed power, interface interactions/angles and finite-face event readings |
| Native completed + unknown face, source/hook coverage failure, invalid arithmetic or 129th hit | unavailable / NATIVE_FINITE_HIT_AUDIT_UNAVAILABLE | Withhold dependent v9 readouts; do NOT accuse upstream of an observed geometry bug |
| Native completed with native warning | Existing warning status retained; geometry safety still required | Warning qualification cannot override inconsistent/unavailable geometry |
| Native completed with all actual Glass hits independently checked | checked / REPRESENTED_FORWARD_FINITE_HITS_CHECKED | Preserve existing native readout gates and Fresnel approximation notes; no blanket physical guarantee |
| Native completed with zero native Glass incidents, positive source/observer coverage | checked-no-hit | Preserve sampled zero only; no continuous-shadow claim |

**Publication must be atomic.** Existing CLI checkCandidate.executionPassed/measurementState, runProblemEvidence, snapshotNativeObservations, evaluateObservables, QualifiedUI/browserExecution, exports and all run revision guards need a reviewed shared gate. It must not hide a completed native run as failed; it must not publish a complete summary.observations alongside withheld results or promote a partial first-face, detector power or native-parentage-like claim. Raw native diagnostics can retain a bounded anonymous failure **reason/count**, but not produce a new trusted path or image from an invalid run. Historical no-opt-in v9 results may deliberately change qualification; other physical families must not gain new keys or statuses silently. A separate source-emissions-only counter can remain as raw emission evidence, but cannot certify downstream v9 physical observations.

## Required adversarial evidence before production implementation

- Actual v9 rotated-37° PR #87 example: native completed but numerical v9 readouts withheld, with explicit machine reason. Translated invalid case remains native failed, not upgraded by a shadow audit.
- Actual true-positive controls: normal incidence, critical±5°, critical±0.001° and scale/translate/rotate variants. Check each real native event with exact **finite** edge membership, not only line crossing. No false refusal on valid forward hits above the unmodified native cutoff.
- Counterexamples: finite face endpoints, a correctly forward but very short genuine step above native cutoff, near-parallel but forward, far outside infinite-line intersection, multiple close faces, legitimate vertex ambiguity, large/small coordinates, rotation, source order, 0/1/2 external passive detectors and detector mutation.
- Full native Fresnel:true and transmitted-only:false/true model controls; multiple source interleaving and weak branch truncation; stopped/undefined/failed/warning conditions; missing/duplicate observer or source callback, fake parent, unknown native surface, 128/129 callback cap, no-hit false-zero.
- Independent raw versus instrumented parity for native processed, truncation, undefined, emitted, signed detector power, first/face events and their exact return-object references. Real Chrome must expose "native completed but numerical evidence withheld" without displaying accepted stale metrics; A→B→A genuine delayed old-browser callback control and portable qualified reimport/export behavior.
- Historical fingerprints, **all 11 GitHub workflows**, bounded performance of BigInt arithmetic and explicit browser compatibility. New targeted Chat B R2 **implementation** review at its exact head and separate owner merge approval.

Do **not** automatically suppress v5 planar, v7 circle or v8 triangle on evidence proven only for v9. True internal TIR until depth exhaustion remains 'incomplete' as before. Exact-critical incident *angle alone* is not a refusal condition. No altered material indices, photon routes, native colorMode, cutoffs, source brightness, numeric nudging, solver, library upgrade or upstream modification.

## Test-only validation for this design

The accompanying disposable evaluation/finite-hit-forward-qualification-v1/shadow.mjs executes **24 fully specified v9 synthetic scenes × two actual pinned-native runs = 48 runs**, including the 20 exposed PR #87 quadrilateral geometries plus four new normal-incidence controls. It snapshots each actual pre-mutation native incoming ray and actual incident point; checks the unique finite face, the exact binary64 rational forward and cutoff rule, **exact finite segment parameter u**, every callback and a cap, then compares ordinary and instrumented native status, count and first-outcome parity. It produces only a **counterfactual shadow qualification**, not a changed production result. Its extra per-instance research callback wrapper is disposable: the production design requires one owning native wrapper. All original frozen problem data and source evidence stay untouched.

**Independent R2 design review should explicitly challenge**: (1) mandatory v9 suppression semantics and what is withheld, (2) exact finite-face membership and arithmetic, (3) all-callback coverage including zero hits, (4) unknown versus proved contradictory geometry, (5) the 128-callback cap and full Fresnel overhead, (6) raw/summary/browser publication consistency, and (7) any legitimate positive close-hit counterexample. Design review cannot approve nonexistent production code.


## New adversarial evidence: ordinary exact-critical runs are themselves variable

The initial test-only CI of this PR **failed and must remain a recorded failure**. The first captured batch had a translated v9 scene with differing ordinary and instrumented terminal status; a second run captured a rotated v9 scene with **four** ordinary vs **six** instrumented interface incidents. These differences were **not** corrected by changing the authored geometry, source ray, physics, Snell threshold or native core.

A subsequent diagnostic added **eight alternating executions** (four plain canonical runs and four read-only-wrapper runs) for **each** original exact-critical v9 case. In those actual retained runs, plain canonical executions **themselves** varied with run ordering:

- Translated: ordinary statuses included **completed** with 3 incidents and **failed** with 4 incidents (the latter had native invalid face observations), without source changes.
- Rotated 37°: ordinary runs remained completed but had **5 or 6 incidents**, with matching variation in processed segment totals.
- Read-only-wrapper runs also varied, and some individual paired canonical and instrumented runs had different event totals.

**Consequence:** near/exact-critical **cross-execution trajectory equality is not a valid design acceptance oracle** for this pinned native branch. The variation's mechanism (including possible upstream state, V8 optimization, numerical conditioning and wrapper influence) is **not isolated**. Do not assert the wrapper causes the discrepancy merely because two runs differed; equally, do **not** claim behavior-neutral instrumentation is proven merely because some pairs happened to agree. A future release must preserve native return/input invariants **within the same callback and same actual run**, and evaluate every observed forward hit of **that run** before promoting measurements. Ordinary far-from-critical and normal-incidence wrapper parity remains a separate regression requirement. No previous first failed CI report or original PR #87 observation is rewritten.

**Test correction in the draft research script:** the counterfactual shadow qualification now belongs to the **instrumented execution whose events were actually checked**, not to a different ordinary execution's native status. Repeated original exact-critical traces and all status/count discrepancies remain visible in the raw research report. The final research gate tests controlled far-angle/normal invariants, exact finite-segment checks and at least one actual contradictory native event; it does **not** demand all independently executed critical cases reproduce an identical ray history. This is not permission to merge a production gate.

**Additional explicit Chat B design question:** Can the proposed *mandatory v9* numerical qualification be implemented without accidental observation-induced perturbation of the near-critical engine? What exact side-effect, performance, callback-identity and run-local proof should be required if inter-run numerical trajectories are demonstrably unstable? If not provable, a more conservative opt-in research-only diagnostic or withholding narrow near-critical measurements may be preferable to a general mandatory production observer. A separate independent **design** verdict is needed before owner approval to implement.
