## Frozen schedule — 24 fresh-OS-native-process trials

Six blocks, each one trial of all four separate modes, per-block order Fisher–Yates shuffled using experiment-schedule xorshift32 seed **`0x9800A55`**. These are **two different seeds serving different purposes**: experiment schedule ordering and *fixed* native engine seed.

1. `seeded-off`: common test-only seeded native loading; normal original source, detector and Glass observers; **no** optional Stage-1 numerical diagnostic and no extra method TAP.
2. `seeded-on`: same native loading and original source/interface observer path; enable existing Stage-1 finite-hit diagnostic, **no** extra method TAP.
3. `seeded-tap-blackhole`: ON plus exactly one extra `finiteDiagnostic.beforeIncident` diagnostic-method wrapper; copy the same scalar p1/p2/incident values into a bounded array on each native callback and call original method **once**, discard copied points in final report (only totals).
4. `seeded-tap-archive`: same extra method wrapper and hot-path scalar copies as blackhole, but preserve original callback p1/p2/incident scalar arrays after terminal. Retain faces in authored y-up and recorded ray/hit in native y-down, and exact source cutoff separately.

Total **24 runs, 6 per mode**, every one in a fresh Node 24 OS process. Do not install another native-calling Glass.onRayIncident wrapper. The two TAP modes match **code and per-callback copy/push work**, but this is NOT proof of time-equivalent overhead or same-event counterfactual; the number of callbacks and native status may differ. Routine source and detector observers still operate in all four profiles.
