# Frozen comparative protocol — focused vs full LLM context, first attempts

**Research tool only, committed before executing any new model inference.** This protocol is an extension of the previously installed private held-out revision design, not an independent evaluation outcome or a new inference service. No model calls, private questions or references are included in this public PR.

## Question answered

For the **same independently reviewed original investigation and the same verified qualified baseline**, does the optional focused context (existing components, revisions or observations) improve **unedited first-attempt physical-revision fidelity and refusal quality** relative to the original full exploration context? Keep native completion and token/byte costs separate from physical fidelity. Do not infer a teacher-learning outcome or a native optics law.

## Controlled comparison and limits

- Eligible original tasks: existing-component `revise` or `observe` actions and clear `missing` / `ambiguous` / `unsupported` / `invalid` negatives. **Exclude `structure` tasks** and model-family upgrades: the focused UI does not advertise those actions, so scoring them as paired failures would be unfair. Independently adjudicated references are frozen **before** exposure; the private preflight refuses a supported `expectedAction:'structure'`.
- Use **2, 4, 6, 8, 10 or 12** genuinely unseen independent source-backed question/baseline pairs, balanced by task family, physical edit, passive observation and legitimate refusal if possible. Include two actual independent physics reviewers with adjudicated canonical final physics and allowed target types. Strings alone cannot prove reviewer identity. Questions, references, consent and provider credentials remain private, outside Git/Actions. Existing exposed lens/mirror/glass software fixtures are allowed **only for MOCK harness tests**, not held-out LLM success claims.
- Freeze original `questions.json`, `reference.json`, their SHA-256 and case order using the **existing** `evaluation/heldout-exploration-v1/commit.mjs`. A separately saved, timestamped pre-inference commitment and confirmed reviewer independence are required. The comparison order and format are fixed in this publicly committed protocol and runner before inference.
- For each source case, make exactly **two** independent, stateless single-turn API calls **to the same explicitly authorized model/provider/config**: one `full`, one `focused`. Prompt skeleton, task text, baseline qualified scene/source notes and expected envelope are common. The **only purposefully varied prompt content is the exported exploration context**: original `explorationContext(baseline,task)` versus `focusedExplorationContext(baseline,task)`. Both preserve the *entire same qualified baseline hash*. Full may contain unrelated structure descriptions; both receive identical instruction to choose existing `revise`/`observe` or `cannotAuthor`.
- **Counterbalance order:** for 0-based frozen case position `i`, even positions run `focused` then `full`; odd positions run `full` then `focused`. This gives equal number of first-position contexts across any even number of cases. No adaptive selection, reordering after observing results, regeneration of prompts or using one answer as context for the other. Both responses independent requests, no conversation history.
- Before sending, calculate SHA-256 of the exact per-arm messages and record both original serialized byte sizes (and model-reported token counts if supplied). Preserve one unedited raw response per arm, first-attempt SHA, model ID and provider usage; **no parsing repair, automatic retry, answer substitution, cached model response, hidden scoring reference or alternate model**. If a call fails, retain completed earlier calls, record the interruption and **do not automatically resume**.
- External inference is **disabled by default**. Only after user selects a provider/model, has rights to transmit all private question/baseline text, agrees to the specific **two calls per source question** and possible charges, explicitly sets provider/transfer authorization, and configures a private API key can the manual capture CLI send calls. This ChatGPT project user's broad development approval is **not** automatically provider/data/charge consent. A ChatGPT subscription does not provide API credentials. No secrets in GitHub.
- Validate first-attempt hashes and raw response files **before** opening the precommitted reference. Then reuse existing strict proposal validator, canonical scene schema, `scoreExplorationRevision`, `scoreExplorationDecline`, native PhyDemo execution and typed requested-result evaluator. Independently grade negative decline reasons with real reviewers; a decline is only **provisional** without human judgment. Reject incorrect missing/malformed changes as first-attempt failures, never repair them.
- Report **paired case-level denominators** separately for full and focused: raw valid envelopes, exact requested physical deltas, matched targets, structural/unsupported actions (not admitted for paired trial), native-completed accepted revisions, genuine engine rejections, legitimate declines pending human rationale review, mean context JSON bytes and provider-reported token usage if present. Do **not** pool with Track A full-scene authoring or earlier synthetic/mock runs. Do not produce a combined model-accuracy score or assert a statistically significant improvement from a tiny pilot.
- **Strict boundary:** No PhyDemo patch, new optical solver, native seed policy, source interpretation default, geometry tolerance, Stage-1 accepted optical result or mandatory Stage-2 withholding. This is evaluation infrastructure only, and no new provider is connected automatically. Production integration requires normal CI and honest research/evidence review.

## No-model execution and falsification

Run included offline synthetic MOCK tests for both arms to show: exact baseline identity; balanced order; 2 calls per task and no repair; frozen raw response files; reference never imported by capture; changed question/reference hash refusal; malformed attempt retained; independent postcapture scoring and native execution; existing private path restrictions and refusal to write existing output directories. Mock outputs **are not** independent LLM responses or teacher/student outcomes.

**Release gate:** This protocol and scripts can merge as software-only infrastructure after code review and 11 standard CI workflows. The actual comparison is **NOT RUN** until real private data/reviewers/provider approvals are separately supplied and immutable first attempts actually captured.
